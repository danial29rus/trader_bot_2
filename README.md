# LVLUP — бот доната в игры

Telegram-бот на `aiogram 3` и PostgreSQL для доната в мобильные и онлайн-игры: внутриигровая валюта десятков игр, Robux и карты Roblox, игровые карты (PlayStation, Xbox, Nintendo, Razer Gold…) и ключи игр для консолей и ПК (не Steam). Бот запоминает игровой ID: в «🎮 Мои игры» следующий донат делается в один тап. Корзина, личный кабинет, бонусы, промокоды и поддержка работают в одном чате.

Внутренняя поддержка работает в том же Telegram-чате: клиент создаёт обращение в «💬 Поддержка», а оператор отвечает из браузерной админ-панели или через `/admin` в боте. Переписка сохраняется в PostgreSQL.

Данные, необходимые для подключения платёжного провайдера, перечислены в [docs/LEGAL_AND_PAYMENTS_READINESS.md](docs/LEGAL_AND_PAYMENTS_READINESS.md).

## Быстрый запуск

1. Скопируйте пример конфигурации и задайте как минимум `BOT_TOKEN`, `POSTGRES_PASSWORD` и `ADMIN_IDS`:

   ```bash
   cp .env.example .env
   ```

2. Запустите сервисы:

   ```bash
   docker compose up -d --build
   ```

   Контейнер `bot` перед long polling автоматически выполняет `alembic upgrade head`. Проверить состояние можно через `docker compose logs -f bot`.

3. Для демо-каталога (без ключа поставщика) выполните:

   ```bash
   docker compose exec bot python -m scripts.seed_demo
   ```

   Затем в Telegram: `/start` → две разные позиции → корзина → оформление.

## Конфигурация

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | токен бота Telegram; не коммитить |
| `DATABASE_URL` | async SQLAlchemy URL, в Docker уже указывает на `db` |
| `ADMIN_IDS` | Telegram ID администраторов через запятую |
| `STORE_NAME`, `SUPPORT_CONTACT`, `RULES_TEXT` | тексты интерфейса |
| `RESELLCODES_API_KEY` | серверный ключ ReSellCodes, необязателен |
| `USD_TO_RUB_MINOR` | фиксированный настроенный курс: копеек за 1 USD; пусто — поставщикские товары остаются в USD |
| `BACKUP_INTERVAL_SECONDS`, `BACKUP_KEEP_DAYS` | период и срок хранения дампов (по умолчанию 24 часа / 14 дней) |
| `ADMIN_USERNAME` | единственный логин для локальной админ-панели |
| `ADMIN_PASSWORD_HASH` | Argon2-хэш пароля администратора; обычный пароль сюда не записывается |
| `ADMIN_JWT_SECRET` | случайный секрет не короче 32 символов для сессий панели |
| `ADMIN_WEB_PORT` | порт панели, по умолчанию `8080` |
| `LEGAL_DOCUMENT_DATE` | дата редакции публичных документов |
| `LEGAL_OPERATOR_NAME`, `LEGAL_CONTACT_EMAIL` | реквизиты оператора и контакт; заполнить до включения приёма платежей |

Интерфейс работает как «одна панель»: каждый экран редактирует одно сообщение бота с баннером своего раздела (`assets/banners/*.jpg`, стиль ретро-аркады). Баннеры рисуются с нуля командой `python -m scripts.make_banners` (нужен Pillow из `requirements-dev.txt`, шрифты macOS); разделы, заголовки и цвета задаются в `scripts/make_banners.py`.

## Админ-панель

Панель доступна только локально по `http://localhost:8081`. В ней отображаются счётчики, пользователи, заказы и обращения поддержки; ответ оператора сохраняется в базе и отправляется пользователю в Telegram.

Перед первым входом задайте пароль, не помещая его в файл:

```bash
docker compose run --rm admin-api python -m admin_api.password
```

Скопируйте напечатанный Argon2-хэш в `ADMIN_PASSWORD_HASH` файла `.env`. Затем задайте `ADMIN_JWT_SECRET` случайной строкой из 32+ символов и перезапустите API:

```bash
docker compose up -d admin-api
```

Пока эти две переменные пусты, панель намеренно не принимает вход и показывает инструкцию по настройке.

## База, миграции и резервные копии

Схема создаётся миграцией `0001_initial`. Повторно применить миграции вручную:

```bash
docker compose exec bot alembic upgrade head
```

`db-backup` делает custom-format `pg_dump` в том `postgres_backups`; дамп не лежит в git и переживает перезапуск контейнеров. Для восстановления используйте отдельный одноразовый контейнер/`pg_restore` после выбора конкретного файла. Перед production стоит дополнительно реплицировать этот том в удалённое, зашифрованное хранилище: локальный Docker volume не защищает от потери хоста.

## Каталог: разовая выгрузка из ReSellCodes

`scripts/snapshot_import.py` один раз забирает у ReSellCodes популярное: донат в ~60 игр (`TOPUP_BRANDS`), Roblox, игровые карты (`GIFT_CARD_BRANDS`) и ключи популярных игр для консолей и ПК без Steam (`KEY_GAMES`), с картинками, регионами и условиями поставщика. Списки — в начале `services/snapshot_service.py`. Клиент поставщика выполняет только GET-запросы; методов заказа в коде нет. Обновлять каталог автоматически не нужно, цены дальше ведутся в админке.

```bash
# 1. Посмотреть реальные ответы поставщика (~9 запросов, ничего не записывает)
docker compose run --rm bot python -m scripts.snapshot_import --probe
# 2. Выгрузка: цена = цена поставщика × курс × (1 + наценка), с округлением вверх до рубля
docker compose run --rm bot python -m scripts.snapshot_import --usd-rub 95 --markup 15
```

- Скрипт держит темп 25 запросов в минуту и не превышает `--budget` (по умолчанию 1500; дневной лимит поставщика 5000).
- Если выгрузка прервалась или упёрлась в лимит, повторите ту же команду. Уже выгруженные категории пропускаются, `--refresh` скачивает их заново.
- `--sections topups,roblox,giftcards,keys` позволяет выгрузить только часть разделов. Списки брендов задаются в начале `services/snapshot_service.py`.
- Цена, изменённая в админке, помечается 🔒 и не перезаписывается при повторной выгрузке. «Массовая наценка» в админке пересчитывает цены из сохранённой цены поставщика.

## Проверки

Локальные маленькие тесты без базы:

```bash
pip install -r requirements-dev.txt
pytest -q
```

Для полноценного smoke-test после запуска: `docker compose exec bot python -m scripts.seed_demo`, затем пройти сценарий выше. Никогда не добавляйте `.env` с токенами в репозиторий.
